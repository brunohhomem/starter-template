## Tarefa T6 — Fila, processor, worker e limpeza

### Decisões relevantes da spec

**Decisão 3.5 — Token no payload do job:**
Job carrega o token em claro. Mitigação: `removeOnComplete: true`, `removeOnFail: { age: 3600 }`, `attempts: 5`, backoff exponencial de 10s. Risco aceito e documentado.

**Decisão 3.6 — Worker separado:**
Processo separado (`apps/api/src/worker.ts`, `NestFactory.createApplicationContext`). A API só enfileira; nunca processa. Em testes, o worker sobe dentro do processo do teste.

**Decisão 3.7 — Falha ao enfileirar:**
Não derruba a operação principal. Loga `warn` sem dados pessoais e segue.

**Decisão 3.16 — Limpeza:**
Job diário no worker: apaga sessões expiradas há mais de 7 dias e tokens de e-mail expirados há mais de 7 dias.

### Bloco Fila (de R4)

**Fila `mail`**: jobs `send-email-confirmation`, `send-password-reset`, `send-invite`. Payload validado com zod **no processor** (entrada tratada como `unknown`):
```typescript
{ to: string /* email */, token: string, expiresAt: string /* ISO */ }
```
Opções padrão: `attempts: 5`, `backoff: { type: 'exponential', delay: 10000 }`, `removeOnComplete: true`, `removeOnFail: { age: 3600 }`.

Erro 4xx do Resend ou e-mail inválido lança `UnrecoverableError` (importado de `bullmq`).

**Fila `maintenance`**: job repetível `cleanup-expired`, cron `0 6 * * *` (UTC), registrado no boot do worker, idempotente.

### O que implementar

#### 1. `MailQueueService` (produtor) — `apps/api/src/modules/mail/mail-queue.service.ts`

```typescript
@Injectable()
export class MailQueueService {
  async enqueue(job: MailJob): Promise<void>
}
```

Onde `MailJob` é uma union:
```typescript
type MailJob =
  | { type: 'send-email-confirmation'; payload: { to: string; token: string; expiresAt: string } }
  | { type: 'send-password-reset'; payload: { to: string; token: string; expiresAt: string } }
  | { type: 'send-invite'; payload: { to: string; token: string; expiresAt: string } };
```

- Usa BullMQ `Queue` da fila `mail`
- Falha silenciosa: se o `add` lançar, loga `warn` (sem dados pessoais) e **não relança**
- Opções de job: `attempts: 5`, `backoff: { type: 'exponential', delay: 10000 }`, `removeOnComplete: true`, `removeOnFail: { age: 3600 }`
- Conexão BullMQ própria com `maxRetriesPerRequest: null`

#### 2. `MailProcessor` (consumidor) — `apps/api/src/modules/mail/mail.processor.ts`

- BullMQ `Worker` da fila `mail`
- Recebe `job: Job<unknown>` — valida o payload com zod antes de usar
- Schema zod para o payload: `z.object({ to: z.string().email(), token: z.string(), expiresAt: z.string() })`
- Se a validação falhar: lança `new UnrecoverableError('Invalid job payload')` (sem retry)
- Para cada tipo de job:
  - Monta o link com `WEB_ORIGIN` (sem barra dupla):
    - `send-email-confirmation`: `${WEB_ORIGIN}/confirm-email?token=${token}`
    - `send-password-reset`: `${WEB_ORIGIN}/reset-password?token=${token}`
    - `send-invite`: `${WEB_ORIGIN}/accept-invite?token=${token}`
  - Calcula `expiresInLabel` com `formatExpiresInLabel` usando os TTLs da config
  - Renderiza com `renderEmail(...)` (chaves camelCase: `emailConfirmation`, `passwordReset`, `invite`)
  - Chama `MailService.sendNow({ from: env.MAIL_FROM, to, subject, html, text })`
- Erro `UnrecoverableError` para: e-mail inválido, payload malformado, erro 4xx do transporte
- Para testar erros 4xx: o `MailService.sendNow` pode lançar um erro com `status` 4xx — verifique se é 4xx e lance `UnrecoverableError`

#### 4. `MaintenanceProcessor` — `apps/api/src/modules/maintenance/maintenance.processor.ts`

- BullMQ `Worker` da fila `maintenance`
- Job `cleanup-expired`:
  - Deleta da tabela `email_tokens` onde `expires_at < (now() - interval '7 days')`
  - Deleta da tabela `sessions` onde `expires_at < (now() - interval '7 days')` (use Drizzle com `lt` e `sql\`now() - interval '7 days'\``)
  - Loga quantos foram deletados (sem dados pessoais)
- Usa `@Inject(DATABASE)` para obter o Drizzle db

#### 5. Worker entry point — `apps/api/src/worker.ts`

```typescript
import 'reflect-metadata';
import { NestFactory } from '@nestjs/core';
import { loadEnv } from './config/load-env';
import { WorkerModule } from './modules/worker/worker.module';
import { Logger } from 'nestjs-pino';
import IORedis from 'ioredis';

async function bootstrap() {
  const env = loadEnv();
  const app = await NestFactory.createApplicationContext(WorkerModule, { bufferLogs: true });
  app.useLogger(app.get(Logger));

  // Registra job scheduler para cleanup-expired
  const connection = new IORedis({
    host: env.REDIS_HOST,
    port: env.REDIS_PORT,
    password: env.REDIS_PASSWORD,
    maxRetriesPerRequest: null,
  });

  const { Queue } = await import('bullmq');
  const maintenanceQueue = new Queue('maintenance', { connection });

  // upsertJobScheduler (BullMQ v5+) ou fallback com add+repeat
  // Verifique se maintenanceQueue.upsertJobScheduler existe antes de usar
  if (typeof (maintenanceQueue as unknown as { upsertJobScheduler?: unknown }).upsertJobScheduler === 'function') {
    await (maintenanceQueue as unknown as { upsertJobScheduler: (name: string, repeatOpts: unknown, template: unknown) => Promise<void> }).upsertJobScheduler(
      'cleanup-expired',
      { pattern: '0 6 * * *' },
      { name: 'cleanup-expired', data: {} },
    );
  } else {
    await maintenanceQueue.add('cleanup-expired', {}, {
      repeat: { pattern: '0 6 * * *' },
      jobId: 'cleanup-expired',
    });
  }

  await maintenanceQueue.close();
  await connection.quit();

  console.log('[worker] Workers iniciados e scheduler registrado');
}

void bootstrap();
```

**Nota importante:** Verifique a API real do BullMQ v6.4.0 em `node_modules/bullmq/dist/esm/interfaces/` antes de escrever o código de `upsertJobScheduler`. O objetivo é não duplicar o job repetível ao reiniciar o worker.

#### 8. Testes de integração — `apps/api/test/mail-queue.int-spec.ts`

Testes obrigatórios (use Redis e MemoryTransport reais):

1. **Job processado entrega 1 mensagem**: enfileira `send-email-confirmation`, aguarda processamento, verifica `memoryTransport.sent.length === 1`
2. **Payload inválido não envia e vai para falha sem retry**: job com payload sem `to` → `UnrecoverableError` → `job.isFailed()` sem retentativas
3. **Erro recuperável retenta**: mock que falha 2 vezes e passa na 3ª → `job.isCompleted()`
4. **Erro irrecuperável não retenta**: `UnrecoverableError` → `failedReason` contém o erro, `attemptsMade === 1`
5. **Após completar, job não existe mais no Redis**: `removeOnComplete: true` — após `job.isCompleted()`, buscar o job por id e verificar que é `null`
6. **`cleanup-expired` apaga sessões e tokens vencidos há mais de 7 dias e preserva os recentes**
7. **Registrar o scheduler duas vezes não duplica**: chamar `upsertJobScheduler` (ou equivalente) 2x e verificar que há apenas 1 job repetível
